Random (well-grouped) validation split
==================================================

Why grouped by well_uid, not a plain random row split:
  each well contributes ~78 near-duplicate rows (same location,
  same aquifer, overlapping rain history). A row-level shuffle
  would leak the same well into train and valid. Grouping by
  well_uid keeps the split 'random, not by year' while keeping
  each well's rows on one side only.

valid       32,539       414     15.0%
test        32,382       414     15.0%

wells appearing in more than one split: 0 (must be 0)
